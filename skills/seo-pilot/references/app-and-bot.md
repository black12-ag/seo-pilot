# App and bot discovery

## App Store and Google Play

Read `marketingskills:aso` and its relevant platform references. Identify the actual listing URL, platform and locales from provided context or connected authorized sources. A missing app target does not block a website audit; report app work as not assessed rather than inventing a listing or delaying independent website work.

Audit current title/subtitle or short description, category, factual description, screenshots and previews, localization, support links and review themes. Check current field limits and eligibility against the platform's documentation before drafting edits. Do not claim hidden keyword fields were inspected from a public listing. Screenshots and conversion data are unknown when unavailable.

Separate Apple and Google indexing behavior. For example, Apple's platform-version reference currently describes the keyword budget in bytes, so count encoded bytes for multilingual fields rather than relying on a generic character-count check. Use current official sources:

- https://developer.apple.com/app-store/search/
- https://developer.apple.com/help/app-store-connect/reference/app-information/platform-version-information/
- https://support.google.com/googleplay/android-developer/answer/9898842

Draft requested listing changes using real app features. Tie a proposed test to a measurable store outcome. Writing drafts is not authorization to publish listings, launch paid ads, alter billing, post review replies or buy keyword data.

## Telegram and other public bots

For Telegram, verify current features at https://core.telegram.org/bots/features and https://core.telegram.org/bots/api. Other platforms require their own documentation.

Check public display name, about/description, supported language variants, profile image, website/app destinations and startup/product deep links. Keep brand identity and product facts consistent with public canonical pages. Public marketing/support pages can support discovery; private conversations and customer delivery screens are not public SEO content.

Inspect existing command/payload parsers before proposing a deep-link format. Route identifiers may select a screen but must not authorize identity, payment, price or delivery. Preserve project-specific command ownership and transaction behavior. Test navigation without making a purchase.

If requested, draft profile text and deep-link mappings; publish only within the user's actual authorized scope. Do not rename an established bot username or claim a Telegram ranking improvement from keyword stuffing. Report observed referral visits and conversions separately from unmeasured discovery.
